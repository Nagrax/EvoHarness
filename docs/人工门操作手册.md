## EVO-H1 · DE-24 人工耗时基线

**缺什么**：真人处理询价样本的耗时样本。当前 `human_verdicts: 0`、无任何计时记录。

**你要做的**（约 2~3 小时，可分几次）：

1. 生成任务单（已生成）：`eval/runs/human-gates/h1-plan.json`
2. 按单中口径逐条计时。核心要求：
   - 从**开始阅读题面**到**产出字段齐全的交付结论并自查完**
   - `net_seconds` = 净工作时间，扣除环境搭建/等待模型/打断
   - 每条独立计时，**不要事后回忆估算**
   - ≥10 条，≥2 个操作者更好
3. 写成 `h1-timing.json`，格式：

```json
{
  "repo_revision": "814ccb9",
  "operator_ids": ["你"],
  "records": [
    {
      "case_id": "qq-xxxxxxxx",
      "started_at": "2026-11-22T09:00:00+08:00",
      "ended_at": "2026-11-22T09:11:30+08:00",
      "net_seconds": 690,
      "operator": "你",
      "tooling": "浏览器 + 飞书",
      "notes": "中途被打断 2 分钟已扣除"
    }
  ]
}
```

4. 核验：

```powershell
python -X utf8 eval/human_gate.py h1-check eval/runs/human-gates/h1-timing.json
```

**会被拒绝的情况**（fail-closed，都是真实出现过的坑）：
- 缺 `operator` 等任一字段
- `net_seconds` 大于起止时间的墙钟跨度（数据自相矛盾）
- `net_seconds > 8 小时`（不像单题耗时）
- 缺记录级元数据（`repo_revision` / `protocol_sha256` / `operator_ids`）

**核验通过后**：把 `mean/median_seconds` 与三臂结果（固定SOP 6/108、原生 101/108、有界 93/108，
见 `eval/runs/threearm-20261121/COMPARISON.md`）按同一题单对齐，才能谈"节省多少人工"。
在此之前**不得宣称效果收益**。

## EVO-H2 · DE-13 语义真值独立审阅

**缺什么**：模型归因结论（124 份，`SKILL_ISSUE=121` 等）没有独立人工真值。
台账明确 `label_status=provisional`。

**你要做的**：

1. 盲审清单已生成：`eval/runs/human-gates/h2-checklist.md`（124 份中抽 60 份，确定性等距抽样）
2. **盲审规则（重要）**：清单里只给「哪个错误项失败」与执行轨迹引用，
   **不含**模型给的类别、置信度、建议动作。请不要去翻 `cases/*.json` 的 `proposal` 字段，
   否则就失去独立性了。
3. 逐条判定，可选词表固定五类：
   `SKILL_ISSUE / CASE_ISSUE / HARNESS_ISSUE / ENVIRONMENT_ISSUE / UNCERTAIN`
   —— **不确定就选 UNCERTAIN，不要强行归类**。
4. 写成 `h2-review.json`：

```json
{
  "reviews": [
    {
      "case_id": "qq-00446bacf7efba3f",
      "verdict": "SKILL_ISSUE",
      "reviewer": "你",
      "reviewed_at": "2026-11-22T09:30:00+08:00",
      "rationale": "轨迹显示 read_file 未授权后仍按旧价格作答，属技能正文缺约束"
    }
  ]
}
```

5. 核验并计算人机一致率：

```powershell
python -X utf8 eval/human_gate.py h2-check eval/runs/human-gates/h2-review.json `
  --attribution eval/runs/attribution-20261121
```

**会被拒绝**：`verdict` 不在五类词表内、`rationale` 为空、`case_id` 重复、缺审计字段。

**注意**：工具算出的一致率只描述人机重合度，**不等于真值**。不一致项要逐条复核；
不得因为"一致率高"就宣称模型归因正确。若审阅结论与模型大面积不一致，
那本身是重要发现（说明 EVO-07 的 SKILL_ISSUE 口径需重新审视）。
