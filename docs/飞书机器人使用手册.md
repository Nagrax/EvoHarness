# 飞书接入

飞书是 EvoHarness 的可选渠道，组织与工作状态由根产品服务维护。

1. 安装根依赖后，安装 `feishu-daily-agent/requirements.txt`。
2. 复制 `feishu-daily-agent/.env.example` 为该目录的 `.env`，填写自己的应用配置、消息范围、数据库与模型参数。默认先用测试/影子模式核对事件和草稿。
3. 在飞书开放平台配置应用权限、事件订阅与机器人身份。个人身份发送还需本人 OAuth 同意。
4. Web、Worker 与渠道的数据库配置指向同一个绝对路径；例如 Windows 使用 `sqlite:///D:/evo-data/org.db`，Linux 使用 `sqlite:////var/lib/evoharness/org.db`。不要把独立渠道默认库当作另一套组织产品。
5. 在 `feishu-daily-agent` 目录运行 `python scripts/onboard_feishu.py --check` 检查实际凭证和权限，`--discover` 列举可访问会话；按结果配置 owner 和消息范围。

群聊默认无需 @；`FEISHU_GROUP_REPLY_ONLY_MENTION=1` 切换为仅 @ 触发。个人订阅、私聊和组织知识分别授权。自动发送仅在策略、白名单与有效批准均满足后启用；未收到真实回执的发送保留待核对状态。

## 本人 OAuth

配置 `FEISHU_REDIRECT_URI` 与开放平台中的回调一致，本地回调入口为 `http://127.0.0.1:8791/oauth/callback`。设置长期保存的 `FEISHU_TOKEN_SECRET`，并与数据库密文分开备份。个人发送需要有效的用户授权；机器人权限不能替代本人授权。

在渠道目录运行：

```sh
python scripts/oauth_server.py --once --save
```

在浏览器完成本人同意后，程序再次核对 token 对应的用户，并将授权加密写入配置的产品数据库。终端只显示脱敏结果。旧的 `save_twin_auth.py` 仅在显式提供 `--input` 时导入已有授权结果，不再依赖作者机器上的临时文件。

## 启动与停发

从项目根目录运行 `python -m ops.supervisor start`，由主管启动渠道并持续续租；不要同时启动第二个 `main.py`。先使用 `readonly_shadow` 检查读取、草稿与 owner 日报，再按实际批准切换发送模式。`python -m ops.supervisor stop` 请求优雅停机，线上服务使用[统一部署与恢复流程](OPERATIONS.md)。

配置与程序入口：[配置模板](../feishu-daily-agent/.env.example)、[渠道入口](../feishu-daily-agent/main.py)。
